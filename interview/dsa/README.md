# DSA warm-ups — 30 minutes, before the Java work

Two problems a morning, timed. The point is not to finish; it is to recognise
the pattern within the first two minutes.

Each problem file has the method stub, the pattern it belongs to, and a `main`
that checks your answer with no dependencies:

```
mvn -pl core-java compile exec:java -Dexec.mainClass=dev.anish.sprint.dsa.Day01Problems
```

## How to practise so it sticks

1. **Two minutes to name the pattern before writing anything.** If you cannot,
   that is the gap — not your coding speed.
2. **Speak out loud while solving.** Interviewers score communication as much as
   the answer, and silence reads as being stuck.
3. **State the complexity before you run it**, then check whether you were right.
4. **Re-solve a problem you got wrong three days later**, not the same day.
   Immediate repetition only tests your short-term memory.
